# 기기 연결 코드 (짧은 설계)

## 왜
지금은 새 기기를 서버 동기화에 붙이려면 VM에 SSH로 들어가 CLI로 토큰을 만들고, 그 토큰을 손으로 앱에 붙여 넣어야 한다. 이걸 이렇게 바꾼다. 새 기기는 서버 주소만 넣으면 짧은 코드를 보여 준다. 사용자가 그 코드를 이미 연결된 기기나 GitHub Actions에서 승인하면, 새 기기가 자기 토큰을 받는다. 첫 기기도 같은 방식으로 연결한다. 토큰 값은 사람이 보거나 옮기지 않는다.

## 목표 / 비목표
- **목표**
  - 첫 기기를 포함해 모든 기기를 코드 승인으로 연결한다.
  - 기기마다 따로 토큰을 받는다. 그래서 잃어버린 기기 하나만 폐기할 수 있다.
- **비목표**
  - QR 스캔. 사용자가 코드만 쓰기로 정했다.
  - 앱 안의 토큰 목록·폐기 UI. 목록과 폐기는 CLI `token list/revoke`로 한다.
  - CLI `token create`는 그대로 남긴다.
- **실패로 보는 것**
  - 코드만 보고 남이 토큰을 얻을 수 있는 것. 레포가 public이라 Actions 로그와 입력값은 공개된다.
  - 토큰이나 비밀값이 로그에 남는 것.

## 접근
1. **새 기기가 코드를 보여 주고 승인을 기다린다 (채택).** OAuth device flow와 같은 방식이다.
   - 요청할 때 그 기기만 아는 비밀값(secret)이 함께 생기고, 토큰은 그 secret으로만 받아 갈 수 있다. 그래서 코드는 공개돼도 된다.
   - 승인하는 곳은 연결된 기기나 Actions 중 어디든 된다.
2. 연결된 기기가 코드를 보여 주는 방식. 첫 기기에는 코드를 보여 줄 기기가 없다. 그렇다고 서버가 코드를 Actions 로그에 찍으면 공개 로그를 본 누구나 그 코드로 토큰을 받을 수 있다.
3. 기기끼리 직접(로컬 네트워크) 토큰을 전달하는 방식. 두 기기가 같은 네트워크에 있어야 하고, 첫 기기는 여전히 해결하지 못한다.

## 서버 (quilleaf-be)

### 대기 요청 테이블
DB 테이블 `pair_requests`. CLI 프로세스도 승인하므로 메모리가 아닌 DB에 둔다.

| 열 | 내용 |
|---|---|
| `code_hash` | PK. 코드의 해시 |
| `secret_hash` | UNIQUE. secret의 해시 |
| `device_name` | |
| `created_at` | |
| `expires_at` | |
| `vault_id` | 승인 전에는 NULL |
| `client_hash` | 요청한 클라이언트 주소의 해시 |

### 엔드포인트
1. `POST [prefix]/pair`: 인증 없음. 본문 `{"deviceName": "..."}`, 최대 1 KiB.
   - 성공하면 `201 {"code": "K7QM2XPA", "secret": "<32바이트 base64url>", "expiresAt": <epoch ms>}`.
   - 같은 클라이언트 주소(Caddy가 넣는 `X-Forwarded-For`의 마지막 값)의 대기 요청이 3개, 또는 전체 대기 요청이 500개면 `429`를 돌려준다.
2. `POST [prefix]/pair/approve`: `Authorization: Bearer <토큰>`, 본문 `{"code": "..."}`.
   - 승인하는 토큰의 볼트를 요청에 기록하고 `200 {"deviceName": "..."}`을 돌려준다.
   - 코드가 없거나 만료됐거나 이미 승인된 요청이면 `404`.
3. `POST [prefix]/pair/claim`: 본문 `{"secret": "..."}`.
   - 승인 전이면 `202`.
   - 승인됐으면 이때 토큰을 발급한다. 라벨은 deviceName이다. 요청을 지우고 `200 {"vaultId": "...", "token": "..."}`을 돌려준다.
   - secret이 없거나 만료됐으면 `404`.
   - 토큰 원문은 서버에 저장하지 않는다. claim 응답에 한 번만 담긴다.

### 코드
- Crockford base32 8자로 40비트다. 유효 기간은 10분.
- 입력은 정규화한다. 대소문자, 하이픈, 공백을 무시하고, 헷갈리는 문자는 O→0, I/L→1로 바꾼다.
- 만료된 행은 요청이 올 때마다 지운다.

### 대입과 남용
- 승인에는 유효한 토큰이나 VM 접근(CLI)이 필요하다. 코드를 맞혀도 남의 요청을 자기 볼트에 넣을 수 있을 뿐이라 얻는 게 없다. 그래서 실패 횟수 제한은 두지 않는다.
- 인증 없는 `/pair`는 클라이언트 주소마다 대기 요청 3개로 막는다. 전체 500개 상한은 저장 공간을 묶어 두는 용도다. 전체 상한 하나만 두면 익명 호출자 한 명이 그 상한을 채워 모두의 연결을 막을 수 있다(리뷰 지적). 주소는 해시로만 저장한다.

### 기타
- **CLI:** `pair approve <code> <vaultId>`를 추가한다. 이걸로 첫 기기를 승인한다.
- **토큰 라벨:** `tokens`에 `label TEXT` 열을 추가한다. 이미 있는 DB에는 `ALTER TABLE`로 넣는다. `token list`가 라벨을 보여 주고, `token create <vaultId> [label]`로 라벨을 줄 수 있다.
- **워크플로:** `.github/workflows/approve-device.yml`을 둔다.
  - `workflow_dispatch`이고 입력은 `code`와 `vault_id`다.
  - 입력은 정규식으로 검증한다.
  - SSH로 VM에 들어가 `docker compose exec ... pair approve`를 실행한다.
  - deploy와 같은 secret을 쓴다.
- **로그:** 코드, secret, 토큰, deviceName은 남기지 않는다. `pair.requested` / `pair.approved` / `pair.claimed`에는 vaultId와 tokenId만 남긴다.

## 앱 (leaflet, 설정 → 서버 동기화)

### 연결 요청 (새 기기)
1. 서버 주소를 넣고 누르면 코드를 `K7QM-2XPA` 형태로 크게 보여 준다. 남은 시간과 승인하는 방법 안내를 함께 보여 준다.
2. 3초마다 claim을 보낸다.
3. 토큰을 받으면 볼트 ID 설정과 토큰(키체인)을 저장하고 "연결됨"으로 바꾼다.
4. 동기화를 켜는 건 사용자가 스위치로 한다. 첫 업로드 순서를 사용자가 고르게 하려는 것이다.
- git 동기화가 켜져 있으면 켜기 스위치와 같은 메시지로 거절한다.
- 설정 화면을 벗어나거나 10분이 지나면 claim을 멈춘다.

### 기기 승인 (연결된 기기)
- 토큰이 저장된 기기에서만 켜진다.
- 코드를 입력하면 approve를 보내고, 성공하면 "<기기 이름> 연결을 승인했습니다"를 보여 준다.

### 요청 처리
- HTTP 요청은 Rust 명령 `pair_request`, `pair_claim`, `pair_approve`가 기존 `reqwest`로 보낸다. 웹뷰 fetch는 CORS 때문에 쓰지 않는다.
- secret과 토큰은 Rust에만 둔다.
  - secret은 요청마다 Rust 상태에 보관한다.
  - claim이 성공하면 토큰을 키체인에 바로 넣고, 웹뷰에는 vaultId만 돌려준다.
- 서버 주소 `wss://host/sync`는 첨부 블롭 URL과 같은 규칙으로 `https://host/sync/pair...`로 바꾼다.
